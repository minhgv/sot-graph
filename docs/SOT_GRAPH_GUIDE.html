SOT-Graph: Cẩm Nang Toàn Diện MCP Tools & CLI

1. Tổng Quan về SOT-Graph

Trong quy trình phát triển phần mềm hiện đại với các AI Coding Agents (như Claude Code, OpenCode, Antigravity, Pi/OMP), hai trở ngại lớn nhất là sự cạn kiệt cửa sổ ngữ cảnh (Context Exhaustion) và ảo tưởng mã nguồn (Hallucination). SOT-Graph ra đời như một giải pháp nền tảng cung cấp lớp tri thức xác thực tuyệt đối.

Sơ đồ 1: Luồng kiến trúc tổng thể và chu trình dữ liệu trong SOT-Graph

Các Trụ Cột Kỹ Thuật Đột Phá:

  • Zero-Daemon SQLite Storage: Dữ liệu lưu trong .sot/sot.db chạy chế độ WAL (Write-Ahead Logging), đa tiến trình đọc ghi an toàn mà không cần dựng daemon nền.
  • Zero-Token Ingestion Protocol: Thay vì đọc hàng chục file mã nguồn (>100 dòng), Agent chỉ tra cứu graph để lấy hợp đồng chữ ký và callers/callees.
  • Self-Healing & JIT Micro-Reconciliation: Khi một file bị sửa đổi, hệ thống tự động băm lại SHA-256 và cập nhật đồ thị tức thời ngay trước khi trả kết quả truy vấn.
  • Giao thức Bảo đảm P7: Cơ chế kiểm soát chặt chẽ với biên lai trước khi sửa (Scope Receipt) và biên lai tác động sau khi sửa (Diff Impact Receipt).

2. Mô Hình Bằng Chứng & Hệ Nhãn Niềm Tin (Trust Model)

Mọi kết quả trả về từ SOT-Graph đều được phân loại trạng thái vật lý trên đĩa cứng ngay tại thời điểm gọi qua hệ thống nhãn niềm tin (Trust Verdicts):

Nhãn Niềm Tin Ý Nghĩa Chi Tiết Hành Động Của AI Coding Agent
[STRONG] Xác thực vật lý trên đĩa (span-verified): Tệp tồn tại, symbol tồn tại đúng vị trí khai báo, hash nội dung trùng khớp. Độ tin cậy cao cho điều hướng/tái sử dụng; vẫn nên đọc lại snippet — không phải bảo đảm về ngữ nghĩa hay tính đầy đủ.
[WEAK] Khớp ngữ nghĩa / một phần: Tìm thấy tên symbol nhưng chỉ khớp trong chú thích (comment) hoặc token coverage thấp. Bắt buộc phải đọc trực tiếp đoạn mã theo tọa độ dòng (file:start-end) để xác minh lại.
[REBUILT] Tệp đã đổi vị trí: Tệp đã bị đổi tên hoặc di chuyển thư mục nhưng bộ Reconciler đã tự tìm lại được. Cập nhật lại đường dẫn import sang path mới mà công cụ cung cấp.
[REMOVED] Tệp/Symbol đã bị xóa: Từng tồn tại trong quá khứ nhưng hiện tại không còn trên đĩa. TUYỆT ĐỐI KHÔNG tham chiếu, gọi hàm hoặc sinh mã nguồn dùng symbol này.
[NOPATH] Node ảo / Inline node: Node định danh cấu trúc, biến môi trường hoặc dynamic hook không có file riêng. Kiểm tra ngữ cảnh cấu hình runtime.

Sơ đồ 2: Cây quyết định đánh giá và phân loại nhãn niềm tin (Trust Verdict State Machine)

3. Chi Tiết 21+ MCP Tools (Dành Cho AI Coding Agents)

Giao diện MCP (Model Context Protocol) cho phép các tác tử AI gọi hàm trực tiếp theo chuẩn MCP 2025-06-18. Các công cụ hỗ trợ trả về ResourceLink (sot://node/{id}) giúp lấy chi tiết mã nguồn theo nhu cầu (lazy-fetch) mà không gây bùng nổ token.

Nhóm 1: Định Vị & Tìm Kiếm Tri Thức

MCP sot-graph_sot_search
Định vị / Tra cứu

Tìm kiếm các symbols, classes, methods trong đồ thị tri thức kèm theo hệ nhãn niềm tin. Trả về điểm xếp hạng BM25/AST và danh sách URI để fetch chi tiết.

Tham số đầu vào:
  • query (string, bắt buộc): Tên hàm, class, route hoặc từ khóa nghiệp vụ.
  • limit (integer, mặc định: 6): Số lượng kết quả tối đa.
  • scope (string, tùy chọn): Giới hạn tìm kiếm trong thư mục hoặc file cụ thể.
  • threshold (number, mặc định: 0.5): Ngưỡng coverage để xác nhận [STRONG].
// Ví dụ gọi MCP Tool
sot-graph_sot_search({
  query: "ContractCrosscheck",
  scope: "Modules/Api",
  limit: 5
})
MCP sot-graph_sot_map
Bản đồ kiến trúc

Sinh bản đồ mã nguồn thu gọn có kiểm soát ngân sách token (token-budgeted map), xếp hạng các node theo thuật toán Personalized PageRank (PPR).

Tham số đầu vào:
  • focus (string, tùy chọn): Chuỗi các symbols trọng tâm cách nhau bởi dấu phẩy để định hướng PageRank.
  • max_tokens (integer, mặc định: 1024): Giới hạn số lượng token cho bản đồ trả về.
// Ví dụ gọi MCP Tool
sot-graph_sot_map({
  focus: "ContractService,PartnerController",
  max_tokens: 1500
})
MCP sot-graph_sot_notes
Tri thức lưu trữ

Đọc danh sách các ghi chú tri thức (kiến trúc, lỗi đã fix, quy tắc dự án) được lưu trữ từ các phiên làm việc trước đó.

Tham số đầu vào:
  • query (string, tùy chọn): Từ khóa lọc nội dung ghi chú.
  • limit (integer, mặc định: 50): Số lượng ghi chú tối đa.

Nhóm 2: Khảo Sát AST & Mối Quan Hệ Mã Nguồn

MCP sot-graph_sot_explore
Duyệt đồ thị

Duyệt đồ thị quan hệ AST có giới hạn bước nhảy (bounded traversal). Cho biết hàm/class này gọi những ai và được ai gọi tới.

Tham số đầu vào:
  • node_id (string, bắt buộc): ID của node hoặc tên FQN của symbol.
  • depth (integer, mặc định: 1): Độ sâu duyệt quan hệ (hops).
  • limit (integer, mặc định: 100): Giới hạn số cạnh trả về.
MCP sot-graph_sot_usages
Find All References

Tìm kiếm toàn bộ vị trí tham chiếu của một symbol trên toàn bộ codebase, gom nhóm theo từng caller, đồng thời cảnh báo rủi ro trùng tên (bare-name risk).

Tham số đầu vào:
  • target (string, bắt buộc): Tên symbol hoặc method cần tra cứu.
  • scope (string, tùy chọn): Giới hạn trong thư mục con.
MCP sot-graph_sot_implementations
Kế thừa / Đa hình

Xem toàn bộ cấu trúc kế thừa và hiện thực hóa (extends / implements) của một interface hoặc base class, tìm ra tất cả các concrete classes cụ thể.

Tham số đầu vào:
  • target (string, bắt buộc): Tên interface hoặc class cơ sở.
MCP sot-graph_sot_pack
Context Packaging

Đóng gói một k-hop ContextBundle (định dạng YAML) xung quanh một symbol mục tiêu: gồm hợp đồng caller/callee 1-hop và chữ ký hàm 2-hop, nén ngữ cảnh tối ưu cho subagent.

Tham số đầu vào:
  • target (string, bắt buộc): Tên symbol mục tiêu.
  • max_hops (integer, mặc định: 2): Độ sâu liên kết.
  • max_bytes (integer, mặc định: 65536): Giới hạn dung lượng byte.

Nhóm 3: Phân Tích Kiến Trúc & Fact Bundler

MCP sot-graph_sot_architecture_report
Kiến trúc C4

Phân tích toàn diện kiến trúc dự án: phát hiện mô hình phân tầng, các God Nodes, các chu trình phụ thuộc vòng (circular dependencies) và xuất báo cáo markdown.

Tham số đầu vào:
  • scope (string, tùy chọn): Phạm vi đường dẫn phân tích.
  • sigma (number, mặc định: 1.5): Ngưỡng độ lệch chuẩn để gắn nhãn God Node.
MCP sot-graph_sot_communities
Phân cụm Louvain

Sử dụng thuật toán phân cụm Louvain để phát hiện các phân vùng kiến trúc tự nhiên (architectural communities) và tính điểm kết dính (cohesion score).

MCP sot-graph_sot_bundle
Fact Bundler

Trích xuất tự động bộ 5 file Fact Bundle mật độ cao vào thư mục .sot/bundle/: danh mục module, endpoints routing, workflows/states, violations và chỉ số hệ thống.

Nhóm 4: Reverse Engineering & Động Cơ Solution (ITPRO / Manpower)

MCP sot-graph_sot_trace
Full-Stack Trace

Truy vết đường đi thực thi từ sự kiện giao diện Frontend (UI clicks), qua REST API, Controller, Service đến Database. Tự động sinh sơ đồ Mermaid Flowchart và Sequence Diagram.

Tham số đầu vào:
  • target (string, bắt buộc): Mã ticket (VD: `CRMCM-107`), tên chức năng hoặc route API.
  • depth (integer, 1-5, mặc định: 2): Độ sâu liên kết qua các tầng.
MCP sot-graph_sot_ui_tree
Frontend UI AST

Bóc tách cây quyết định UI: trích xuất các trường dữ liệu (Form inputs), quy tắc validation, nút bấm (Button Triggers) và sự kiện chuyển đổi Modal/Màn hình (hỗ trợ Flutter, React, Vue, Blade).

MCP sot-graph_sot_backend_flow
Backend Steps

Bóc tách các vi bước xử lý backend, các nguồn dữ liệu đa dạng (Multi-Datasources), ranh giới transaction và các nhánh xử lý ngoại lệ (Exception Handling).

MCP sot-graph_sot_solution_inventory
Stage 1 Discovery

Nhóm 5: Git Diff Impact, Assurance Receipts & Lịch Sử Commit

MCP sot-graph_sot_diff_impact
Git Diff Blast Radius

Tính toán bán kính ảnh hưởng từ git diff: ánh xạ trực tiếp dòng thay đổi vào AST nodes, tìm kiếm toàn bộ callers bị ảnh hưởng gián tiếp và danh sách test cases cần chạy.

Tham số đầu vào:
  • target (string, mặc định: 'HEAD~1'): Git revision so sánh.
  • staged (boolean): Phân tích thay đổi đã staged.
  • working_tree (boolean): Phân tích thay đổi chưa staged.
  • auto_reconcile (boolean): Đồng bộ đồ thị trước khi chạy.
MCP sot-graph_sot_scope_receipt
Giao thức P7.1

Biên lai PRE-change: Chốt phạm vi an toàn trước khi sửa đổi symbol. Ghi nhận snapshot commit hiện tại, inward callers và bộ test suite tương ứng.

MCP sot-graph_sot_diff_impact_receipt
Giao thức P7.2

Biên lai POST-change: Đóng gói kết quả phân tích git diff sau khi sửa code, đối soát bằng chứng và đưa ra quyết định đóng (closure decision) rõ ràng.

MCP sot-graph_sot_git_history
Chấm điểm rủi ro

Quét lịch sử git commit kèm chấm điểm rủi ro tự động (Low, Medium, High, Critical) dựa trên số dòng thay đổi và mức độ đụng chạm vào các God Node.

MCP sot-graph_sot_verify_drift
Kiểm tra lệch đĩa

Kiểm tra độ lệch giữa CSDL SQLite và thực tế đĩa cứng: phát hiện file bị xóa hoặc sửa đổi nhưng chưa được cập nhật vào đồ thị (an toàn cho CI).

Nhóm 6: Đồng Bộ External Provider

MCP sot-graph_sot_providers_sync
Đồng bộ External

Kích hoạt đồng bộ hóa chỉ mục từ provider bên ngoài (VD: `codebase-memory`), được bảo vệ an toàn bởi project write lock và lưu lại biên lai ledger run.

Tài Nguyên Trực Tiếp (MCP Resources & Subscriptions)

Bên cạnh các Tools, SOT-Graph cung cấp các điểm cuối tài nguyên MCP chuẩn hóa:

  • sot://stats: Trả về thống kê tổng quát về đồ thị (số node, số cạnh, tệp tin, kích thước CSDL).
  • sot://notes: Danh sách toàn bộ các ghi chú tri thức đã lưu.
  • sot://node/{node_id}: Resource template đọc nội dung chi tiết mã nguồn và chữ ký của một node bất kỳ.
  • notifications/resources/updated: Bắn thông báo thời gian thực đến client khi đồ thị có phiên bản thay đổi (generation update).

4. Chi Tiết Hệ Thống Câu Lệnh CLI

Bộ công cụ dòng lệnh (CLI) của SOT-Graph được thực thi qua lệnh sot. Đây là công cụ chủ lực cho lập trình viên trên Terminal, kịch bản tự động hóa (Bash scripts) và CI/CD Pipelines.

Nhóm Lệnh Vòng Đời & Đồng Bộ CSDL

sot reconcile

Đồng bộ hóa đồ thị với tệp trên đĩa một cách lũy kế (idempotent), tự động bỏ qua file không đổi nhờ bảng journal.

# Đồng bộ toàn bộ codebase
sot reconcile

# Đồng bộ chỉ một file hoặc một module cụ thể
sot reconcile Modules/Api/Services/ContractService.php

# Ép quét lại toàn bộ (bỏ qua journal hash)
sot reconcile --force

# Chỉ định 4 luồng worker song song và kích thước batch
sot reconcile --workers 4 --batch-size 128

# Xuất biên lai xác thực (Assurance Receipt) dạng JSON
sot reconcile --receipt --json

sot watch

Theo dõi sự thay đổi file trên đĩa cứng theo thời gian thực và tự động reconcile ngay lập tức.

# Chạy watcher tương tác trực tiếp
sot watch --debounce-ms 200

# Khởi chạy chạy nền dưới dạng Daemon
sot watch -d

# Kiểm tra trạng thái Daemon
sot watch --status

# Dừng Watcher Daemon
sot watch --stop

# Cài đặt thành service chạy cùng hệ điều hành (systemd / LaunchAgent)
sot watch --service install

sot verify & sot doctor

# Kiểm tra độ lệch (drift) giữa đĩa và CSDL
sot verify
sot verify --deep   # Băm sâu SHA-256 toàn bộ file

# Kiểm tra sức khỏe toàn diện của CSDL SQLite
sot doctor
sot doctor --receipt --json

Nhóm Lệnh Truy Vấn, Map & Pack

# Tìm kiếm symbol kèm nhãn niềm tin
sot search "ContractCrosscheck" -n 5 --scope "Modules/Api"

# Tìm kiếm Hybrid (kết hợp văn bản và vector similarity)
sot search "tính toán công nợ" --hybrid

# Lập bản đồ repo theo ngân sách token (Personalized PageRank)
sot map --tokens 1024 --focus "ContractService,PartnerController"

# Khảo sát quan hệ AST xung quanh một symbol
sot explore "App\\Services\\PaymentService" --depth 2

# Tìm toàn bộ nơi gọi hàm (Find All References)
sot usages "approveContract"

# Xem các lớp con hiện thực hóa interface
sot implementations "PaymentGatewayInterface"

# Đóng gói k-hop ContextBundle YAML làm context cho AI Agent
sot pack "OrderService" --max-hops 2 --tokens 1500 -o order_bundle.yaml

# Lưu ghi chú tri thức hoặc quyết định kỹ thuật quan trọng
sot insert --title "Lưu ý kết nối Oracle DB" \
           --body "Không dùng raw SQL thiếu schema prefix. Dùng DB::connection('oracle')->..." \
           --keywords "oracle,db,connection"

Tìm kiếm hàm/class có nhãn niềm tin sot_search(query="...") sot search "..."

Xem cây kế thừa interface/class sot_implementations(target="...") sot implementations "..."
Đóng gói ContextBundle YAML sot_pack(target="...") sot pack "..." -o bundle.yaml
Truy vết Full-Stack (sinh Mermaid) sot_trace(target="...") sot trace "..." -o trace.md
Bóc tách cây giao diện Frontend sot_ui_tree(component="...") sot ui-tree "..."
Bóc tách vi bước xử lý Backend sot_backend_flow(service="...") sot be-flow "..."

Bóc tách bảng vi bước Manpower (Stage 2) sot_solution_steps(method="...") sot solution steps "..."

Bán kính ảnh hưởng Git Diff sot_diff_impact(target="HEAD~1") sot diff-impact HEAD~1

6. 4 Kịch Bản Vận Hành Thực Chiến (Workflows)

Quy trình 1: Onboarding nhanh vào codebase lạ (Zero Token Waste)

  1. Chạy sot reconcile --workers 4 để trích xuất đồ thị CSDL chỉ trong vài giây.
  2. Agent gọi sot_map(max_tokens=1024) để nắm ngay các Class/Service nắm giữ nhiều liên kết nhất.
  3. Kỹ sư chạy sot viz --open mở đồ thị tương tác để xem sự phân bố cụm modules trên trình duyệt.
  4. Chạy sot report để kiểm tra danh sách God Nodes và vi phạm kiến trúc cần chú ý.

Quy trình 2: Refactor mã nguồn an toàn theo chuẩn 4 bước

  1. Định vị: Agent gọi sot_search("processPayment") nhận nhãn [STRONG].
  2. Biên lai Trước (P7.1): Gọi sot_scope_receipt("processPayment") để khóa chặt danh sách callers và candidate tests.
  3. Chỉnh sửa: Dùng edit tool sửa chính xác trong phạm vi dòng (file:start-end).
  4. Biên lai Sau (P7.2): Gọi sot_diff_impact_receipt() để xác nhận zero regression và cập nhật đồ thị bằng sot reconcile.

Quy trình 3: Tự động hóa Tài Liệu Giải Pháp (TLGP) & Manpower

  1. Chạy sot solution inventory để phát hiện và phân loại toàn bộ tính năng theo User Role.
  2. Chạy sot solution steps để sinh bảng 4 cột có code AST thật phục vụ điền file Excel nhân công.
  3. Chạy sot solution bundle để sinh ContextBundle.md làm dữ liệu duy nhất cho toàn bộ các subagent hạ tầng.

Quy trình 4: Tự động hóa Git Hooks & CI/CD

  1. Chạy sot setup --hooks để cài đặt git post-merge và post-checkout hook.
  2. Mỗi lần lập trình viên git pull hoặc đổi nhánh, đồ thị tự động được cập nhật trong nền.
  3. Trong CI/CD pipeline, chạy sot verify --deep để đảm bảo mã nguồn và đồ thị luôn đồng nhất.
